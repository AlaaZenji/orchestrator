# Durable Execution & Failure Recovery Specification

## 1. Scope & Objective

This specification details the exact, deterministic system behavior for every anticipated failure scenario in the distributed agent orchestration lifecycle.

---

## 2. Failure Matrix & Deterministic System Behaviors

| # | Failure Scenario | Trigger & Detection | Immediate System Action | Recovery & Eventual State |
| :- | :--- | :--- | :--- | :--- |
| 1 | **Agent Process Crashes (OOM / SIGKILL)** | Worker process exits unexpectedly; exit code $\ne 0$ captured by supervisor; lease expires if uncaptured. | Supervisor marks execution `FAILED`. Emits `io.orchestrator.execution.failed`. Releases lease. | Evaluates `retry_count < max_retries`. If true, increments `retry_count`, transitions Work to `RETRYING`, applies exponential backoff, then marks `ELIGIBLE`. If false, transitions Work to `FAILED`. |
| 2 | **Agent Process Hangs / Deadlocks** | Watchdog detects: `now() - last_heartbeat > heartbeat_timeout_seconds`. | Watchdog marks lease expired. Sends `SIGTERM` to worker process; after 15s grace period sends `SIGKILL`. | Execution marked `TIMED_OUT`. Retry policy evaluated. New execution attempt scheduled with incremented fencing token. |
| 3 | **Orchestrator Host Crashes Suddenly** | Orchestrator process terminated (power loss / kernel panic / host migration). Active workers remain running or orphaned. | No immediate action (orchestrator is dead). Workers continue until lease expires or completion call fails. | On orchestrator restart, **Reconciliation Sweep** executes: queries all `RUNNING` works whose leases expired. Resets them to `ELIGIBLE` or `FAILED`. Replays pending outbox events. |
| 4 | **Database Temporarily Unavailable** | Orchestrator / Worker database connection pool throws connection refused or timeout errors. | Worker enters backoff loop; holds candidate artifacts in local sandbox; refuses to acknowledge task complete. Orchestrator rejects incoming API calls with HTTP 503 Service Unavailable. | Once DB recovers, workers resume heartbeating and retry commit. No state is lost; in-flight transactions that did not commit WAL are rolled back cleanly. |
| 5 | **Network Partition Between Worker and Orchestrator** | Worker cannot reach Orchestrator API to send heartbeat or commit. | Worker local timer detects communication failure; after 2 missed heartbeats worker pauses tool calls. Orchestrator detects lease expiry. | Orchestrator reassigns work (fencing token advanced to $N+1$). When partition heals, partitioned worker attempts write with token $N$, receives 409 Conflict, cleans up local workspace, and terminates. |
| 6 | **Model Provider API Fails (HTTP 500 / 429 Rate Limit)** | Agent runtime captures provider exception during LLM call. | Runtime applies jittered exponential backoff (e.g. 1s, 2s, 4s, 8s up to 60s). Emits `io.orchestrator.agent.api_error` warning event. | If rate limit persists past threshold, execution is failed with `API_QUOTA_EXHAUSTED` error. Work transitions to `RETRYING` with delayed backoff. |
| 7 | **Tool Call Hangs / Infinite Loop** | Tool execution exceeds configured `tool_timeout_seconds` (default: 60s). | Tool gateway terminates the tool subprocess or aborts HTTP socket. Returns error JSON to agent: `{"error": "Tool execution timed out after 60s"}`. | Agent loop observes tool error and decides whether to retry tool, choose alternative approach, or fail gracefully. Orchestrator heartbeat continues unbroken. |
| 8 | **Worker Machine Disappears Permanently** | Hardware failure / spot instance termination without shutdown notification. | No signals received. Lease expires on DB clock after `lease_ttl`. | Reconciliation loop reaps expired lease. Work returned to `ELIGIBLE` pool for other workers to claim. |
| 9 | **Human Approver Waits 8 Hours** | Work transitions to `AWAITING_APPROVAL`. Worker yields or pauses. | Lease is released or suspended; worker process is safely shut down to free CPU/RAM. Work remains safely parked in `AWAITING_APPROVAL`. | Database state is durable; zero compute resources consumed while waiting. When human approves via CLI/API, work moves to `ELIGIBLE` and is picked up immediately. |
| 10| **Human Rejects Approval** | Human operator clicks "Reject" or runs `orchestrator reject <work-id> --reason="..."`. | Work transitions to `CANCELLED`. Rejection reason recorded in audit log. | Any candidate artifacts are discarded. Dependent downstream tasks in DAG are marked `CANCELLED` (cascade). |
| 11| **Artifact Upload Fails** | Network error during upload of large git patch or build output to object store. | Worker retries upload with exponential backoff. Does NOT invoke completion API until storage confirms digest write. | If upload permanently fails, execution marked `FAILED`. Candidate changes discarded; shared repository remains untouched. |
| 12| **Worker Returns After Lease Expiration (24 Hours Later)** | Stale worker unfreezes and calls `CompleteExecution(token=41)`. | Orchestrator executes atomic verification: `WHERE fencing_token = 41`. Fails because active token is 42. Returns HTTP 409 Conflict. | Stale worker's changes are discarded. Zero corruption of current state. |
